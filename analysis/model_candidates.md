## Bonsai(PrismML)について

**エキスパート・ストリーミングの対象には使えない。**

- Bonsai 系はすべて dense(Qwen3 / Qwen3.5 系の dense モデルを 1bit・ternary 化したもの)。MoE 版は公式には無く、予定も見つからなかった。
- **「3bit 版」は存在しない。** 公式の量子化は 1bit(affine bits=1、gs128)、ternary(bits=2 の枠に {-1, 0, +1})、AWQ 4bit の 3 系統。第三者の 3bit 変換も見つからなかった。
- MLX 版は README で PrismML の MLX フォークを案内している。
  - 1bit は標準 mlx の対応ビット幅外とみられる(推測、実機未検証)。
  - Ternary-Bonsai-2 は `prism_hadamard_qwen35` という独自 model_type で、同梱ローダが必須。

dense としての使い道(いずれも未検証):
- **投機デコードのドラフト**: Qwen3 系の Ternary-Bonsai-1.7B / 4B(2bit)。Qwen3-30B-A3B とトークナイザが同じ可能性が高く、標準 mlx で動く見込み。Phase 4(アイデア 8)の候補になる。
- **比較の参照点**: Bonsai-27B-mlx-1bit(5.16GB)を「常駐する dense 27B」として、ストリーミング MoE と tok/s を比べる。ただし MLX フォークが要り、8GB 機ではメモリが厳しい。

- すべて mlx-lm で `SwitchGLU` 実装。今の差し替えがそのまま効く見込み(実機未検証)。
- 3 と 7 は重みのキー名や 8bit の gate がある。再配置ツールの調整が要るかもしれない(推測)。
- 外したもの:
  - Nemotron-3-Nano-30B-A3B: MoE が GLU でない `SwitchMLP`。
  - Mixtral-8x7B: 1 エキスパート約 99MB で粗すぎる。
  - Phi-3.5-MoE: 1 エキスパート約 44MB で粗すぎる。
  - Hunyuan-A13B: 45GB。
  - GLM-4.5-Air: 4bit で 60GB。

## 推奨順

1. **Qwen3-Coder-30B-A3B**: 追加実装なし。ドラフトも共通で使える。
2. **ERNIE-4.5-21B-A3B**: 12.3GB と小さい。粗いエキスパートで、読み出し粒度の効果を見られる。
3. **Qwen3.6-35B-A3B**: 新アーキ。細かいエキスパート × 256 個。

## 100B 超の MoE(2026-10-16 調査)

HF からヘッダだけ取り、`tools/repack.py` の配置計算で常駐部とエキスパートのサイズを出した。速度の上限は「ヒット率 50% と仮定したときの読み出し量 ÷ 帯域」で、机上の推測。
